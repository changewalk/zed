You help a code reviewer read a diff in the best order.

Below is a list of the changed files, with their git status, line counts, and the first changed lines of each. Put the files in the order a careful reviewer should read them.

Rules for the order:
- Start with the file that carries the main behaviour change, the one every other file depends on.
- Follow the dependencies: a caller after the function it calls, a test after the code it tests.
- Put evidence next: tests, fixtures, and eval outputs.
- End with files a reviewer can skim: generated code, lock files, formatting, renames, and config.

Rules for the reason:
- One short sentence, at most twelve words, in plain English.
- Say what the file does in this change, not what the file is.

Reply with a JSON array only, no prose before or after it. Each element has two fields: "path", copied exactly from the list, and "reason". Include every file exactly once.

Example:
[
  {"path": "src/loop.rs", "reason": "The retry loop that every other change serves."},
  {"path": "src/loop_test.rs", "reason": "Proves the loop stops after three retries."},
  {"path": "Cargo.lock", "reason": "Lock file update, skim."}
]
